# WORKFLOW: 借书登记（Borrow）

- **Version**: 0.1
- **Date**: 2026-10-26
- **Author**: @specialized-workflow-architect
- **Status**: Draft
- **Implements**: 需求(4) 借书登记 / 在馆状态同步

## Overview

管理员为读者登记借书：校验读者与图书状态 → 在单事务内创建借阅记录并将图书置为"借出"。触发：管理员菜单"借书登记"。产出：一条在借记录 + 图书状态变更。

## Actors

| Actor | Role in this workflow |
|---|---|
| 管理员（UI） | 输入读者编号 + 书号，接收回执/错误 |
| BorrowService（BLL） | 业务校验 + 事务编排 |
| BorrowDao / BookDao / ReaderDao（DAL） | 参数化 SQL |
| SQL Server | 持久化 + 外键/CHECK 兜底 |

## 前置状态机

- **图书**：`在馆(1) ⇄ 借出(0)`；借书仅允许在 `在馆` 态
- **读者**：`正常 → 注销`；借书仅允许在 `正常` 态
- **借阅**：`在借(ReturnDate IS NULL) → 已还(ReturnDate 非空)`；超期是观察态（在借 ∧ DueDate < 今天）

## 工作流树（含全部边界情况）

```
借书登记
│
├─ 1. 输入读者编号（UI 校验：非空、长度 10、R 开头）
│   ├─ BC-01 读者不存在 ─────────→ E1001「读者编号不存在」→ 返回重输
│   └─ BC-02 读者已注销 ─────────→ E1002「该读者已注销，不可借书」
│
├─ 2. 输入书号（UI 校验：可解析为正整数）
│   ├─ BC-03 图书不存在 ─────────→ E1003「书号不存在」
│   └─ BC-04 图书不在馆 ─────────→ E1004「该书已借出，当前不在馆」
│
├─ 3. 业务规则校验（BLL：事务外预检，事务内复检）
│   ├─ BC-05 在借数量 ≥ 类别可借上限 → E1005「已达可借数量上限(N 本)」
│   └─ BC-06 存在超期未还图书 ────→ E1006「有超期图书未还，请先归还」（假设 A1）
│
├─ 4. 事务执行（SqlTransaction，默认 READ COMMITTED）
│   ├─ 4.1 BEGIN TRAN
│   ├─ 4.2 条件更新：UPDATE Books SET IsAvailable = 0
│   │        WHERE BookId = @id AND IsAvailable = 1
│   │   └─ BC-07 受影响行数 = 0（并发抢先 / 预检后状态变化）
│   │            → ROLLBACK → E1004（重试安全：书确已被他人借走）
│   ├─ 4.3 读取类别可借天数，DueDate = 今天 + MaxBorrowDays
│   │        （跨月/闰年由日期 API 处理，禁止手动算术）
│   ├─ 4.4 复检在借数量（BC-10）：SELECT COUNT(*) WITH (HOLDLOCK)
│   │        若 ≥ 上限 → ROLLBACK → E1005
│   ├─ 4.5 INSERT INTO Borrows(...)
│   │   └─ BC-08 外键/CHECK 违反（理论不可达，DB 兜底）
│   │            → ROLLBACK → E9000「系统错误，请重试」+ 日志
│   └─ 4.6 COMMIT
│       └─ BC-09 COMMIT 前连接中断 → SQL Server 自动回滚
│                → 提示重试（幂等安全：书仍标记在馆）
│
└─ 5. 结果输出
    ├─ 成功：回执（书名 / 读者名 / 应还日期）
    └─ 失败：错误码 + 用户可读消息（不暴露 SQL 细节）
```

## 输入校验失败（步骤 1/2 之前）

| 输入 | 校验规则 | 失败提示 |
|---|---|---|
| 读者编号 | 非空、`^R\d{9}$` | 「编号格式应为 R + 9 位数字」 |
| 书号 | 可解析为 int 且 > 0 | 「书号须为正整数」 |

## 交接契约

```
HANDOFF: UI -> BorrowService
  PAYLOAD:      { readerId: string(10), bookId: int, operatorId: int }
  SUCCESS:      { borrowId: int, dueDate: date }
  FAILURE:      { code: E1001|E1002|E1003|E1004|E1005|E1006|E9000, message: string }
  TIMEOUT:      5s（SqlCommand.CommandTimeout）
  ON FAILURE:   UI 显示 message；E9000 可重试，业务错误码返回菜单

HANDOFF: BorrowService -> DAL（DbHelper.ExecuteInTransaction）
  PAYLOAD:      [ { sql: string, params: SqlParameter[] }, ... ]   // 顺序执行
  SUCCESS:      { rowsAffected: [int, ...] }
  FAILURE:      SqlException → BLL 捕获 → Rollback → 映射 E9000
  TIMEOUT:      5s / command
  ON FAILURE:   Rollback 全部步骤，向 BLL 上抛结构化异常
```

## 可观测状态（关键节点）

| 节点 | 用户看到 | 数据库状态 | 日志 |
|---|---|---|---|
| 预检通过 | 「确认借书：…」 | 无变更 | — |
| 4.2 之后 | （无，事务中） | Books.IsAvailable=0（未提交，外部不可见） | — |
| COMMIT 后 | 成功回执 + 应还日期 | Borrows +1 行；Books 置 0 | INFO 借书成功 reader/book/due |
| 失败 | 错误消息 | 与事务前完全一致（已回滚） | WARN 错误码 + reader/book |

## 错误码表

| 码 | 含义 | 可重试 |
|---|---|---|
| E1001 / E1003 | 读者 / 图书不存在 | 否（重输） |
| E1002 | 读者已注销 | 否 |
| E1004 | 图书不在馆 | 是（换书） |
| E1005 | 达到可借上限 | 否 |
| E1006 | 有超期未还 | 否 |
| E9000 | 系统错误（事务回滚） | 是 |

## 并发与时序假设（显式标记）

- **T1**：步骤 3 预检与步骤 4 提交之间存在窗口期 → 不依赖预检结果，由 4.2 条件更新 + 4.4 复检闭合
- **T2**：DueDate 基于事务内数据库时间（`GETDATE()`），避免应用机与数据库机时钟漂移

## 假设清单（未经操作者确认的决策）

| # | 假设 | 影响边界 | 若不成立 |
|---|---|---|---|
| A1 | 有超期未还不可再借 | BC-06 | 删除该分支 |
| A2 | 每类别每年序号上限 999（3 位） | 读者编号溢出 | 扩至 4 位（CHAR(11)），同步 UI 正则 |
| A3 | 一条图书记录 = 一本物理书 | IsAvailable 语义 | 引入副本表（超出本迭代） |
| A4 | 超期不罚款，仅提示 | 还书展示 | 需求变更时另立工作流 |

## 附：还书流程边界（反向事务，详细契约见 docs/05）

| # | 边界 | 处理 |
|---|------|------|
| RC-01 | 借阅记录不存在 | 明确提示，不误报"已归还" |
| RC-02 | 重复还书 / 并发双还 | 条件更新 `WHERE ReturnDate IS NULL`，行数=0 → 提示「已归还」（幂等） |
| RC-03 | 超期归还 | 计算 (ReturnDate - DueDate) 天数并展示（A4：不罚款） |
| RC-04 | 部分失败 | UPDATE 借阅 + UPDATE 图书同一事务，任一失败全回滚 |
| RC-05 | 还书日期 < 借出日期 | CHECK 约束拒绝（DB 兜底） |
| RC-06 | 图书状态同步遗漏 | 事务保证原子；审查清单 B1 专项检查 |

| # | 操作 | 预期 | 实测输出 / 数据库状态 | 结论 |
|---|---|---|---|---|

| BC-02 | 菜单 3→4 注销 `R092026002` 后，为其借书号 3 | E1002 | `[成功] 读者已注销。` → `[失败] [E1002] 该读者已注销，不可借书。` | 通过 |

> **BC-08 实现差异（需知悉）**：`BorrowService` 仅映射 E1001~E1006（及还书的 E2003），**未实现本文档约定的 E9000 分支**；若外键/CHECK 真被触发，异常会落到 `AdminMenu` 的通用 catch，UI 显示「操作失败: <异常消息>」，而非 `[E9000] 系统错误，请重试`。当前业务路径下该分支不可达（BLL 已先校验读者/图书存在性），故仅作数据库兜底验证。后续可选：补 E9000 映射，或修订本文档的错误码表。

### 结论

- 16 个用例全部执行，行为与文档预期一致；BC-08 的数据库兜底有效，但存在"E9000 未映射"的实现/文档差异（详见上方注记）。
- R1（两终端同时借同一本书）实测仅一个成功，另一请求返回 E1004，数据库中该书只有一条在借记录 —— 条件更新 `WHERE IsAvailable=1` + 受影响行数判定生效。
- 并发双还（RC-02）未产生重复更新：`WHERE ReturnDate IS NULL` 的受影响行数判定使第二个请求走"已归还"分支。
- BC-09 / RC-04 两类"中途失败"场景均验证到无残留脏数据，事务原子性与自动回滚符合预期。
